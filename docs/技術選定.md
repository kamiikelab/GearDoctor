# 技術選定

**自分でサーバーを置かず、端末上で動かす**方針です。2026-08-17 に採用しました。対象はロードバイクに乗り、タイヤなどを自分で交換する人です。

以前（2026-08-17）は TypeScript / Next.js の PWA を採用していました。Strava 連携と画面表示のために常時起動のサーバーが必要で、サーバー設置が難しい条件には合いません。

## 結論

**可能です。ソースは一つ（Dart / Flutter）。Android は GitHub Releases の APK。Google Play には出さない。iPhone は無料の App Store アプリ。**

言語と枠組みは **Dart + Flutter** を推奨します。データは端末内（SQLite）に置きます。Strava はアプリから直接呼びます。

## 何が可能で、何が難しいか

| 条件 | 可否 | 補足 |
| --- | --- | --- |
| 自分のサーバーを置かない | 可能 | アプリとデータは端末の中 |
| Android で使う | 可能 | GitHub Releases の APK。Play には出さない |
| 同じソースで iPhone 用を作る | 可能 | Flutter は Android / iOS を同じソースからビルドできる |
| サーバーもストアもなしで iPhone に入れる | ほぼ非現実 | 仲間に SideStore 等を強いるか、Apple 開発者登録が必要 |
| Strava から走行距離を取る | 可能 | トークン交換に client secret が必要。少人数アプリならアプリ内に置く |

「端末上で動く」は、部品の記録・距離の集計・判定が端末で完結する、という意味です。Strava から記録を取るときだけインターネットは使います。

GitHub Pages のような静的ホスティングは「サーバー設置」よりずっと軽いですが、今回の希望は端末アプリなので、ここでは使いません。

## 配布

| 何を渡すか | 手段 | 誰向け |
| --- | --- | --- |
| ソースコード | GitHub（kamiikelab/GearDoctor） | 開発する人 |
| Android 本体 | GitHub Releases の APK | Android で使う人 |
| iPhone 本体 | App Store（Codemagic → App Store Connect） | iPhone で使う人 |

Android は APK をダウンロードし、「提供元不明のアプリ」を許可して入れます。**Google Play には出しません。**

iPhone は同じソースから IPA を作り、App Store で出します。

- App Store に出す: 年額の開発者登録と審査。無料アプリ
- 自分の iPhone だけ Xcode で入れる: 開発者自身なら可能。配布の手段にはしない
- 非公式のサイドロード: 7 日ごとの再署名などがあり、使わない

そのため **iPhone の配布は App Store、Android の配布は GitHub Releases** です。GitHub の Release は Apple に送りません。

## 採用スタック

| 層 | 提案 | 理由 |
| --- | --- | --- |
| 形 | Flutter アプリ | 一つのソースで Android / iOS をビルドできる。APK を手元で作れる |
| 言語 | Dart | Flutter の言語。TypeScript は使わない |
| データ | 端末内 SQLite | サーバー不要。部品・交換履歴・取得済み距離を端末に置く |
| 走行データ | Strava API をアプリから呼ぶ | client secret はアプリに含める |
| 配布 | Android は GitHub Releases の APK。iPhone は App Store。Play には出さない | サーバーは置かない |

TypeScript / Next.js はサーバー前提だったため、この条件では使いません。TypeScript のまま端末アプリにするなら Expo（React Native）もありますが、APK を自分の PC だけで出す手順は Flutter の方が単純です。

## Strava と秘密情報

Strava は認可コードをトークンに替えるとき、client secret を要求します。本来はサーバーに置くものですが、サーバーを置かない以上、アプリに含めます。

いまの Android 配布（GitHub Releases の APK）では、アプリに含めます。iPhone の App Store でも同じです。Strava の開発者登録自体は、以前どおり必要です（ストア登録とは別です）。

## 通知

方針は変えません。アプリを開いた（または Strava を同期した）ときに、交換後の距離としきい値を比較して表示します。端末のローカル通知は後から足せます。サーバーからのプッシュは使いません。

## 採用しない案

- **自分で立てる Next.js / PWA**: サーバーが必要
- **Swift と Kotlin の二本立て**: Android 主なら過剰
- **iPhone への非公式サイドロードを前提にする**: 使う側の負担が大きい
- **GPX 手入力だけにして Strava を捨てる**: 可能だが、当初の価値が落ちる。Strava がどうしても無理なときの予備

PC での作り方と入れ方は [開発と配布](開発と配布.md)（[Android](開発と配布-Android.md) / [iPhone](開発と配布-iPhone.md)）を参照してください。

## 次に決めること

画面と骨格、Strava の認可と走行取得は実装済みです。PC での起動と Android SDK の要否は [開発と配布（Android）](開発と配布-Android.md) を参照してください。残件は同期の失敗時のやり直しです。
